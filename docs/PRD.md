# 第一部分：产品定位与目标用户

## 1.1 产品核心理念

DayStep 的核心理念是：

Small Steps, Big Progress.

将大目标拆解为每天可以完成的小步骤。

用户不需要自己手动规划所有任务。

用户只需描述：

- 想要完成的目标
- 当前情况
- 目标期限
- 每日或每周能够投入的时间
- 已有大纲或参考资料
- 个人限制与偏好

系统便能够生成一份合理、可修改的执行计划。

计划应包含：

长期目标 → 阶段里程碑 → 子项目 → 每周计划 → 每日任务 → 执行步骤。

随后用户按步骤打卡，系统记录实际完成情况、计算进度、每日评分并进行周期复盘。

## 1.2 面向所有公众开放

本产品不能局限于数学、英语、学生学习或教师管理。

普通用户应该能够使用 DayStep 管理：

- 外语学习
- 考试备考
- 运动健身
- 阅读
- 工作项目
- 职业发展
- 习惯养成
- 个人技能
- 其他自定义目标

学习只是 DayStep 的一个应用场景。

## 1.3 目前已经明确的真实使用场景

### 场景 A：个人成长

平台创建者本人需要管理：

- TOEFL 托福备考
- 健身训练
- 大学课程
- 日常计划
- 自定义长期目标

需要自动规划时间、拆解任务、逐步打卡、记录成果并计算进度。

### 场景 B：台湾学生

包括：

- 台湾高三学测备考学生
- 台湾小学六年级学生
- 台湾国中八年级学生
- 未来更多学生

台湾学生主要通过手机 H5 网页使用 DayStep，不依赖微信。

老师可以布置计划、查看完成情况、审核作业并进行批改。

### 场景 C：中国大陆学生

包括：

- 大陆初中数学学生
- 未来更多不同年级的学生

学生主要通过微信小程序使用。

支持每日任务、步骤打卡、作业上传、老师批改、成绩反馈和进度管理。

### 场景 D：其他公众用户

普通用户可以独立注册和使用 DayStep。

不需要绑定老师。

可以自主制定目标、获得智能计划、执行打卡并查看成长报告。

# 第二部分：平台与跨端架构

## 2.1 必须支持的平台

DayStep 需要有三个主要使用环境：

### A. 微信小程序

用于中国大陆学生和普通微信用户。

支持：

- 账号登录
- 创建目标
- AI 目标拆解
- 目标地图
- 每日任务
- 详细步骤打卡
- 图片和文档上传
- 每日评分
- 查看反馈
- 历史记录
- 进度统计

### B. 手机 H5 网页

用于台湾学生以及其他不使用微信的用户。

必须具备与微信小程序基本一致的核心功能和视觉体验。

### C. 电脑 Web App

主要用于：

- 老师管理多个学生
- 布置学习计划
- 查看学习进度
- 下载作业
- 在线或离线批改
- 发送反馈
- 进行目标规划
- 使用个人成长空间

电脑端还需要适合普通用户使用的个人目标管理页面。

## 2.2 技术选型

优先评估以下架构：

- Taro + React + TypeScript
- Web H5 + 微信小程序跨平台构建
- PostgreSQL
- 云端用户认证
- 服务端访问权限
- 统一后端 API
- AI 规划服务
- 私有对象存储
- 日志与错误监控

可考虑 Zustand、Day.js、Zod、Vitest 等工具，但必须先检查兼容性。

技术选择不能只考虑开发方便，还必须考虑：

- 中国大陆网络可用性
- 台湾用户网络可用性
- 微信小程序 API 限制
- 云服务成本
- 数据安全
- 后期维护
- AI 调用成本
- 扩展能力

对于 Supabase 等云服务，可以作为候选方案，但不能未经实际验证就认定适用于所有大陆及台湾用户。

## 2.3 核心架构原则

采用统一业务逻辑、多平台适配设计。

业务逻辑与平台 UI 分离。

核心功能应尽可能复用：

- 目标管理
- 计划生成
- 任务拆解
- 步骤打卡
- 评分
- 学习记录
- 教师审核
- 数据访问逻辑

微信与 Web 平台的登录、文件选择、文件上传、通知、路由、缓存等功能单独适配。

不允许在业务核心模块中直接依赖微信 API 或浏览器 DOM API。

## 2.4 数据同步

微信小程序、手机网页和电脑网页使用统一云端数据库。

要求：

- 用户重新登录后能恢复记录
- 任务数据跨设备同步
- 学生提交后老师端能够收到更新
- 断线后能重新获取数据
- 云端写入失败时明确提示
- 防止重复提交
- 不允许静默丢失打卡数据

云端数据库是权威数据来源。

本地缓存用于性能优化和适当的离线体验。

# 第三部分：用户账户和权限体系

## 3.1 用户类型

建立统一用户账号系统。

一个用户可以同时具有不同的空间角色。

角色包括：

### 普通用户

创建和执行个人目标。

### 学生

完成老师布置的学习任务、打卡、提交作业、查看批改反馈。

### 监督者

例如老师、教练、导师。

负责规划、检查和审核获得授权的目标。

### 平台管理员

负责平台配置、必要的运营管理和系统安全。

平台管理员不应默认无条件浏览所有用户的私人内容。

## 3.2 账户体系

支持不同平台用户使用自己的账号。

微信端支持符合微信平台规则的登录方式。

Web 端支持适合台湾及其他地区用户的认证方式。

统一内部 User ID。

允许用户在安全验证后绑定多个登录方式。

避免同一个用户在微信与网页产生两套互不相通的账号数据。

## 3.3 多空间系统

一个用户可以拥有：

- 个人空间
- 一个或多个被监督的学习空间
- 其他经过授权的项目空间

老师能够管理多个学生。

每位学生有独立的：

- 档案
- 目标
- 计划
- 任务
- 成果
- 作业
- 批改记录
- 成绩
- 统计数据

学生之间的数据严格隔离。

老师个人的托福、健身及其他私人目标不得被学生访问。

## 3.4 学生邀请机制

采用老师邀请制。

流程：

1. 老师创建学生档案。
2. 系统生成邀请链接或邀请码。
3. 学生通过微信或网页注册并接受邀请。
4. 系统验证邀请码。
5. 学生加入自己的学习空间。
6. 老师获得相应的授权管理权限。

邀请码应支持有效期、次数限制及撤销。

未成年人账户及监护人同意等事项，必须遵循适用的法规和平台要求。

# 第四部分：AI 智能目标规划系统

这是 DayStep 最核心的竞争力之一。

## 4.1 创建目标

用户可以通过自然语言描述目标。

例如：

“我想在接下来的三个月准备托福，每天有两个小时学习时间，我的阅读能力比较弱。”

或者：

“我想每周健身四次，重点提高力量和体能。”

或者：

“我要准备台湾学测数学A，目前排列组合和概率比较弱。”

系统应允许用户提供：

- 目标名称
- 当前水平
- 已完成的进度
- 目标结果
- 截止日期
- 现有大纲
- 时间安排
- 每天可投入时间
- 每周休息时间
- 学习或执行偏好
- 其他限制

支持文字输入。

后续支持通过上传文档导入大纲或项目材料。

## 4.2 AI 目标拆解

AI 根据用户输入生成：

1. 长期目标
2. 阶段目标
3. 可衡量的里程碑
4. 子项目
5. 每周执行计划
6. 每日具体任务
7. 每项任务的步骤
8. 建议完成时间
9. 阶段复盘安排
10. 评分维度及建议

计划必须考虑实际可用时间。

不应生成明显超出用户时间或能力范围的执行任务。

## 4.3 用户确认

AI 生成的内容先作为草稿。

用户能够：

- 展开查看结构
- 修改阶段
- 修改具体任务
- 删除不需要的任务
- 添加新任务
- 更改执行日期
- 调整每日工作量

确认后才正式成为执行计划。

AI 不得未经确认自动修改正式计划。

## 4.4 动态调整

根据以下数据提出计划调整建议：

- 实际打卡完成率
- 任务延期情况
- 实际执行时间
- 任务完成质量
- 学习正确率
- 项目里程碑进度
- 用户反馈
- 距离目标期限的剩余时间

系统可以建议降低任务负荷、增加复习、调整阶段或重新安排进度。

但必须保留原计划及其历史版本。

对于受到老师监督的学生，默认由老师确认重大调整。

# 第五部分：任务拆解与目标地图

## 5.1 五级结构

统一采用：

Goal → Milestone → Project → Task → Step

即：

长期目标 → 阶段里程碑 → 子项目 → 具体任务 → 执行步骤。

系统还需要支持每周计划、任务日期及打卡记录。

不同项目可以灵活省略不必要的层级。

## 5.2 手机目标地图

微信小程序和手机 H5 必须提供完整 Goal Map 页面。

绝对不能把手机端简化成只有任务清单。

页面显示：

- 目标名称
- 最终目标
- 目标期限
- 整体进度
- 当前阶段
- 阶段进度
- 子项目进度
- 任务数量
- 已完成数量
- 下一步行动

使用可展开、折叠的卡片树状结构。

允许用户从总目标逐级展开，直到看到具体步骤。

点击任务可以直接进入完整任务详情。

要求信息层级清晰、操作简洁，不应要求用户点击五次才能完成一次打卡。

## 5.3 完整任务详情

手机端必须具有独立任务详情页。

页面包含：

- 任务名称
- 所属目标
- 所属阶段
- 所属子项目
- 任务说明
- 预计耗时
- 截止日期
- 优先级
- 执行步骤
- 步骤打卡
- 当前完成率
- 附件
- 执行备注
- 成果提交
- 每日评分
- 历史记录

学生模式额外显示：

- 老师要求
- 作业说明
- 作业上传
- 批改状态
- 老师评分
- 批注
- 老师评语
- 订正重交入口

普通用户不必显示教师审核模块。

# 第六部分：每日任务与打卡

## 6.1 今日任务首页

展示：

- 日期
- 今日目标
- 今日任务列表
- 各任务完成率
- 今日总完成率
- 预计投入时间
- 尚未完成任务
- 快速添加任务
- 目标地图入口

## 6.2 步骤打卡

每个任务可以包含任意多个步骤。

支持：

- 单独勾选
- 撤销打卡
- 完成时间记录
- 步骤备注
- 步骤排序
- 添加或删除步骤
- 更新进度
- 任务自动完成判断

无步骤的任务可直接标记完成。

## 6.3 重复任务

支持：

- 单次
- 每日
- 每周
- 自定义星期
- 自定义重复周期

不同日期的任务实例必须独立。

今天完成的任务不能直接让明天的任务显示已完成。

历史记录不得被覆盖。

## 6.4 任务延期

用户可以申请或设置任务延期。

系统应记录：

- 原计划日期
- 新计划日期
- 延期原因
- 延期次数
- 对后续进度的影响

受监督任务可以设置是否需要老师批准延期。

# 第七部分：每日评分与复盘

## 7.1 每日百分制

建立透明的每日成长评分机制。

默认评价维度可参考：

- 任务完成率：50%
- 任务完成质量：25%
- 及时性：15%
- 复盘记录：10%

这些比例只是默认方案，应允许不同类型目标调整。

## 7.2 不同目标使用不同指标

学习目标：

- 完成率
- 练习正确率
- 错题订正
- 学习记录

健身目标：

- 训练完成率
- 训练量
- 训练时间
- 计划执行情况

阅读目标：

- 阅读任务完成率
- 阅读进度
- 总结记录

工作项目：

- 里程碑完成情况
- 交付状态
- 任务质量

不得用一种评分模型强制适配所有目标。

## 7.3 数据可信度

每日执行分数与教师批改分数应分开。

没有客观完成质量数据时，显示未评价。

不得由 AI 随意虚构成绩。

所有评分必须有可查看的计算依据。

评分计算由确定性程序完成，AI 负责解释及建议。

## 7.4 每日与每周复盘

提供：

- 今日完成情况
- 今日得分
- 未完成任务
- 完成质量
- 主要困难
- 明日建议
- 周度进度趋势

复盘结果可以供 AI 生成后续计划调整建议。

# 第八部分：学生管理系统

## 8.1 多学生管理

老师端可创建、查看、编辑和归档学生。

学生数量和类型不能在代码中写死。

学生档案包含：

- 学生昵称
- 地区
- 学段
- 年级
- 科目
- 教材版本
- 课程体系
- 当前水平
- 目标成绩
- 学习困难
- 考试日期
- 备注

支持简体中文与繁体中文。

台湾小学、国中、高中以及大陆各年级应采用可配置的教育体系，不能混淆。

## 8.2 老师功能

老师能够：

- 建立学生目标
- 生成学习计划
- 修改学习计划
- 布置每日任务
- 查看打卡情况
- 查看作业提交
- 下载作业
- 批改作业
- 添加批注
- 填写成绩
- 返回反馈
- 查看订正情况
- 生成学习报告
- 复制学习计划模板

## 8.3 学生功能

学生能够：

- 查看自己的目标地图
- 查看每日任务
- 逐步骤打卡
- 上传作业
- 填写文字说明
- 查看批改状态
- 查看老师评分
- 下载批改文件
- 查看批注
- 进行订正
- 再次提交

学生不得访问其他学生资料。

# 第九部分：作业上传、批改与反馈

这是学生模式的核心模块。

## 9.1 完整流程

老师布置任务 → 学生完成 → 学生上传成果 → 正式提交 → 老师收到待批改记录 → 老师下载或在线批改 → 老师评分、批注与留言 → 发布反馈 → 学生查看 → 必要时订正重交。

## 9.2 学生提交

支持：

- 手机拍照
- 相册多图上传
- PDF 上传
- Word 文档上传
- 其他经过验证的常见文档格式
- 文字说明
- 草稿保存
- 提交确认
- 上传进度显示
- 失败重试

文件上传必须经过格式、大小、权限及安全检查。

## 9.3 老师下载批改

老师可下载学生原始作业。

允许老师使用 Mac、iPad 或其他设备上的软件批改。

老师批改完成后，可以重新上传：

- 批改后的照片
- PDF
- Word 文档
- 其他允许的反馈文件

系统将这些文件关联到对应学生、任务和提交版本。

## 9.4 在线批注

建议分阶段实现。

图片批注需要支持：

- 自由画笔
- 圈选标记
- 文字标注
- 高亮
- 撤销及重做
- 页面缩放
- 保存批注

# 第十七部分：V6.2 标准计划导入

## 17.1 产品优先级调整

DayStep 的基础能力不再依赖内置付费 AI。用户可以使用 ChatGPT、其他外部工具或自行编写计划，再将完整内容导入 DayStep。DayStep 负责确定性解析、结构校验、可编辑预览、用户确认及执行数据生成。

标准计划导入是核心目标管理功能；内置 AI 规划降级为未来可选能力。手动创建目标和任务继续保留。

## 17.2 导入入口与流程

1. 用户粘贴完整 Markdown，或选择 `.md` / `.json` 文件。
2. 系统只在本地或 DayStep 自有服务中解析，不向第三方 AI 发送内容。
3. 用户点击“识别计划”后，系统依据版本化规范生成统一 JSON。
4. JSON Schema 校验通过后进入结构预览；未通过时显示可定位的错误。
5. 预览必须展示目标、阶段、子项目、任务、日期、预计时长、步骤和完成标准。
6. 用户可以修改识别结果并处理所有待确认字段。
7. 只有用户明确确认后才正式写入。
8. 导入完成后生成对应日期的每日任务，并进入现有日历、目标地图、打卡、评分、监督、成果和历史流程。

## 17.3 DayStep Markdown v1 规范

首版解析器必须使用明确字段，不依赖自然语言猜测。正式模板至少支持：

```markdown
# 目标: 三个月内托福达到 100 分
- 开始日期: 2026-11-01
- 截止日期: 2027-01-31

## 阶段: 阅读基础强化
### 子项目: TPO 阅读训练

#### 日期: 2026-11-01
##### 任务: 完成 TPO 54 Passage 1
- 预计时长: 45 分钟
- 完成标准: 完成全文并记录全部错题
- 步骤: 限时完成文章
- 步骤: 核对答案
- 步骤: 分析错题原因
```

字段名称、层级、日期格式、时长单位、允许的重复关系和转义规则必须形成独立版本化规范，并提供可下载模板与有效/无效示例。

## 17.4 内部统一格式

建立版本化 `DayStepPlanSchema`，首版标识为 `daystep.plan.v1`。根对象至少包含：

- `schemaVersion`
- `sourceType`
- `goal`
- `startDate`
- `endDate`
- `milestones[]`
- `projects[]`
- `tasks[]`
- `steps[]`
- `completionCriteria`
- `issues[]`

每个节点必须使用稳定 ID 或导入内临时 ID 建立父子关系。日期使用 ISO 8601 日历日期；时长统一存储为分钟。原始文本、原文件摘要、解析器版本和 Schema 版本必须保留。

## 17.5 缺失信息与排程

- 不猜测缺失日期、阶段或不明确的任务层级。
- 缺失或冲突字段写入结构化 `issues`，分为错误、警告和待确认。
- 存在错误或待确认项时禁止正式导入。
- 允许用户设置计划开始日期和每日可用时间。
- 只有任务顺序与时长明确时，才可用可解释的确定性规则提出排程草案。
- 每条排程建议必须说明依据，并可由用户逐项编辑。
- 无法可靠解析的长文本必须拒绝转换，不得强行拆分。

## 17.6 与现有数据模型整合

导入系统使用暂存层，不建立独立的执行数据库：

1. `PlanImport` 保存原始文本、内容摘要、来源、解析器版本、状态和所有权。
2. `PlanImportDraft` 保存通过 Schema 表达的可编辑结构和待确认问题。
3. 用户确认后，在单一事务中映射到既有 `Goal`、`Milestone`、`Project`、`Task` 和 `Step`。
4. 有明确日期的任务生成 `DailyTaskInstance` 并进入日历。
5. 打卡、评分、延期、教师监督、学生提交、批改和历史记录继续引用既有任务实体。
6. 导入来源通过元数据追踪，不改变任务的通用行为。

## 17.7 安全与一致性

- 导入前必须预览，确认前不得写入正式目标数据。
- 使用用户空间和角色权限校验隔离数据。
- 通过原文摘要、文件摘要和用户空间建立幂等键，检测重复导入。
- 正式写入必须使用数据库事务，任一步失败时整体回滚。
- 新导入不得覆盖既有任务、打卡或历史记录。
- 限制输入尺寸、层级深度、节点数量和字符串长度。
- JSON 必须按白名单 Schema 解析，拒绝未知危险字段、原型污染和恶意构造输入。
- 错误信息必须清晰但不得泄露服务器内部信息。
- 原始计划内容不得在解析过程中发送给第三方 AI。

## 17.8 验收要求

1. Markdown 粘贴、`.md` 和 `.json` 导入均可完成预览。
2. 有效模板可稳定生成相同 JSON。
3. 缺失字段进入待确认状态，不能直接导入。
4. 无效及恶意输入被拒绝并显示可理解错误。
5. 用户修改预览并确认后，目标层级与每日任务一次性写入。
6. 重复导入被识别，且不会重复创建数据。
7. 模拟中途写入失败时不留下部分数据。
8. 导入任务可使用现有打卡、评分、延期、监督、提交、批改和历史功能。
9. 原始文本与解析版本可供用户核对和审计。
10. 测试证明解析过程没有调用第三方 AI API。
